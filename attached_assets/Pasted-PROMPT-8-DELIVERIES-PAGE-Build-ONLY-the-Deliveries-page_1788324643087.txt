Build ONLY the Deliveries page of the existing project.

IMPORTANT:
- Do not redesign or change the existing sidebar/navigation.
- Do not modify the already completed Live Map, Vehicles, Routes, Incidents, or Alerts pages.
- Do not change the existing color palette, typography, spacing system, or overall visual language.
- Do not add a database, authentication, backend, external APIs, GPS services, weather services, routing services, or messaging services.
- Use mock data only.
- Do not create features that are not explicitly requested.
- Reuse the existing components, styling patterns, icons, status badges, tables/lists, detail panels, and mock-data structures wherever possible.

- Medicines

- Commodity

- In Transit
- Delayed

- ETA
- Route Risk
- Current Route

The progress indicator should communicate the delivery stage using the existing mock status.

Example stages can represent:
Planned → In Transit → Delivered

For:
- Delayed
- At Risk

show the appropriate status without falsely implying real-time tracking.

Use text labels in addition to visual indicators.

IMPORTANT DATA RELATIONSHIPS:

Keep delivery data connected to the existing mock datasets.

Delivery → Vehicle
- Vehicle ID must reference an existing vehicle.

Delivery → Route
- Current Route must reference an existing route.

Use consistent existing IDs.

Example:

Vehicle:
V-001

Route:
R-001

Delivery:
D-001

If a delivery uses a vehicle and route, those IDs should resolve to the existing mock datasets.

IMPORTANT:
- Do not create duplicate vehicle or route datasets.
- Do not create conflicting IDs.
- Reuse the existing mock-data source wherever possible.
- Keep relationships consistent with Vehicles and Routes pages.

The detail panel should clearly show the relationship between:

Delivery → Vehicle → Current Route
